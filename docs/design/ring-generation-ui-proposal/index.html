THE AUDIT

What gets in the way

The current editor presents dimensions, appearance, generation controls and a large maths block at once. Short labels such as “Gen” and “Mon” save space but hide meaning. Separate Apply, Use rim and Done actions make it unclear when edits become final.

The wall sample competes with ten presets. The seed preview gives most of its panel to empty space. Errors can replace the entire maths area and truncate useful guidance.

Capture and source notes

Fresh runCreationUiClient captures on current source d35bf21, Minecraft 26.3 Fabric. The fixture completed successfully and creates no world. Its selected wall controls reflect saved test settings; they are not proof of factory defaults. Current in-world generation was audited in source, not captured live for this report.

01 / PROPOSED

Ring

Choose a world size without reading a spreadsheet.

Keep Small, Medium and Large visible, with dimensions and a short explanation of their curvature. Medium stays the recommended starting point. Custom dimensions are always editable; changing one marks the selection Custom.

Clear terms

Around → Circumference. Across → Width. Rim → Wall height. Every field uses blocks. Wall height is measured from the world bottom, not above the ground.

Details on demand

Keep playable area, lap time, radius, chunk count, Atlas memory and generation estimates under one disclosure. Show relevant size warnings without requiring that disclosure.

Honest defaults

Presets change geometry only. Small retains its experimental portal warning. Large is allowed at the current Atlas limit. “Restore saved settings” says what Reset actually does.

02 / PROPOSED

Terrain

Put world-generation choices together.

Move the monument option out of the crowded main button row. Keep the existing three options as labelled on/off controls with one sentence explaining each. No extra submenu or per-page Apply button.

Existing options

More structures, ocean monument search, and continuous ring river remain available. This is a presentation change, not new river or structure-generation work.

Explain restrictions

Below 160 blocks wide, disable monument search and state why next to the control. A search is not a guarantee that a monument can be placed.

World settings only

Archipelago remains hidden. Atlas display detail does not appear here. World data still uses the full one-block source Atlas.

03 / PROPOSED

Walls

Make the chosen wall the main thing on the page.

Give the selected sample roughly half the page. Choose a material from a named list, then select one of three visible patterns. Keep thickness and decay together beside the image. Move the ten presets into a single optional chooser.

Keep the agreed set

All ten materials × three patterns remain: RingWorld Structure, Masonry and Gradient. Default is RingWorld / RingWorld Structure, 7 blocks thick, 10% decay.

An accurate sample

Reuse the 30 existing screenshots. They show material and pattern at fixed 7-block thickness and 0% decay; label that explicitly. Do not imply the image updates for decay or thickness.

Selection without cycling

Show the selected name and let people choose directly. A preset sets material, pattern, thickness and decay; editing any of these marks it Custom. No missing-texture or retired-pattern entries.

04 / PROPOSED

Sky

Show the alternatives instead of hiding them in a cycle.

Give Atmosphere, Night and Void their own labelled choices. Keep Small, Large and None together beneath Sun. This is enough content for a simple tab, with no advanced section.

Know what changes

The sky profile is shared by this world. It changes the visual presentation; it does not change time or gameplay.

Cheap preview

Use small static reference thumbnails in the implemented UI. The drawings here are schematic placeholders, not live renders.

No new settings

Use the existing three backdrop values and three sun values. This proposal adds no sky renderer or new weather controls.

05 / PROPOSED

Preview

Keep the whole-ring overview. Make the terrain readable.

A Medium ring is 64 times longer than it is wide, so fitting the entire map into a panel inevitably creates a thin strip. Keep that strip as an overview and show a selected segment above it at its true aspect ratio.

Useful magnification

Start with a 512 × 256-block segment on Medium. Pan around the circumference using arrows or the overview. Keep a fixed useful zoom first; free zoom can wait.

Same preview worker

Reuse the existing sampled terrain and cancellation logic. The implementation must verify that the local view is useful at the existing sample resolution before adding any extra sampling work.

Truthful states

Seed edits stay in the draft. Show Preparing / Updating / Ready / Unavailable inline; mark an old preview while updating. No structures or caves are promised. The report terrain is illustrative.

06 / PROPOSED

Apply & return

One commit point for the editor.

Apply settings validates the complete draft, saves the RingWorld settings and seed, and returns directly to Minecraft’s Create World screen. Minecraft’s own Create World button remains the action that creates the world. Remove the redundant “Use this RingWorld?” confirmation.

Predictable cancellation

Cancel or Escape returns without changing any setting, including the vanilla seed. Ask to discard only when the draft differs from the entry state.

Keep Minecraft familiar

Retain the existing entry button in the vanilla footer, with a readable label such as “RingWorld: Medium…”. The image is an explanatory return-state mockup, not a proposal for a new mandatory summary screen.

One draft across tabs

Switching tabs, resizing or changing GUI scale must retain edits and validation state. The vanilla screen receives the changes only after successful Apply.

07 / PROPOSED

In-world generation

Lead with progress and the next useful action.

Rework the existing RingWorld Map screen as a RingWorld panel with Generation and Display tabs. The screen currently provides generation status and controls rather than a map; use a name that matches its job.

Progress first

Show the active stage, chunk progress, rough ETA and Pause / Resume. Use “Stop generation…” for the existing Cancel operation. Show stopped and failed states clearly, with the existing restart/retry action.

Keep the details

Move Atlas cells, preview texture stages, elapsed time, rate, build identity and worldgen diagnostics into Technical details. Unknown ETA stays unknown; errors remain visible outside the disclosure.

Respect authority

Only owners/gamemasters get generation actions. Other players see progress and the reason controls are unavailable. Return to game closes this non-pausing panel; work continues only while the world/server runs.

08 / PROPOSED

Local display

Three choices, separate from world creation.

Keep Low, Medium and High in the in-world panel’s Display tab. Medium stays the default. Make it explicit that this setting applies immediately to this player and does not regenerate the world or change anyone else’s settings.

Exactly three levels

Low: 8-block samples / 8-block mesh step. Medium: 2-block samples / 4-block mesh step. High: 1-block samples / 1-block mesh step. Put these details in a disclosure, not the main labels.

Keep the current behavior

Effective mesh resolution remains limited by ring dimensions and GPU capabilities. The full source Atlas stays one sample per block. Keep /ringworld lod low|medium|high.

Scope stays small

Relocate the existing control; do not add a video-settings integration or persistence redesign to this UI pass. Its current session scope stays intact.

09 / RESPONSIVE BEHAVIOR

Small GUI sizes still work

At 320 × 270 logical pixels, use one column with a scrollable body. Keep the tabs and Cancel / Apply footer visible. Reflow fields and the wall preview instead of shrinking text until it becomes unreadable.

Tab order follows the visible page. Arrow keys select within a group, Enter activates a focused control, Escape cancels, and the focused field scrolls into view. Preserve the draft and scroll position when the screen is rebuilt.

The report demonstrates the layout at 320 × 270. It is not a substitute for the existing real-client GUI-scale fixture after implementation. Selected state uses a marker as well as colour; native narration and keyboard focus must be retained.
10 / STATES & DIALOGS

Clear outcomes

Keep confirmations for work with a meaningful consequence: generating real chunks, stopping that job, discarding edits, or restoring a saved configuration. Applying a valid editor draft should simply return to Create World.

11 / IMPLEMENTATION SCOPE

Build the simple version first

This is a UI refactor using the existing configuration, preview worker, sample images and generation service. The zoomed preview is the only substantial new interaction. Implement it after the shared editor and control layout are settled.

1. Shared editor

One draft for dimensions, generation, walls, sky and seed. A common header, five tabs, scroll area and footer. Reuse native Minecraft widgets; the HTML skin is a visual reference.

2. Page layout

Move the current controls into their tabs. Reuse all wall samples, fix cancel semantics, use clear validation text, and present in-world progress and local detail separately.

3. Preview & validation

Add a fixed zoomed segment and overview navigation using the current preview data where possible. Run UI fixtures across GUI scales and supported versions/loaders, then review in game.

Acceptance checks before calling it finished
  1. Each setting appears once in the right place; all ten materials and three patterns have the correct sample, and defaults are preserved.
  2. All pages work at normal size and 320 × 270. Keyboard navigation, focus, narration and scrolling remain usable. Resize and GUI-scale changes retain draft values.
  3. Apply commits the whole draft once. Cancel restores the entry state including seed. Restoring saved settings and switching tabs never leave partial changes behind.
  4. Small, Medium, Large, custom inputs and over-limit inputs produce correct feedback. Monument width restrictions and world-creation lock behavior remain accurate.
  5. Preview reroll, rapid seed changes, cancellation, failure and screen exit do not leak workers, accept stale output or create a world.
  6. Generation start/pause/resume/stop, completion, failure and multiplayer permissions use authoritative state. Local detail still changes live and independently for each player.

No new world formats, renderer changes, Archipelago exposure, river redesign, live 3D previews or launcher integrations are part of this proposal.
