# Patterned underside and Atlas walls

Owner approved replacing the lowest bedrock layer with the wall appearance, then requested matching Atlas walls.

`RingGenerationBoundary.installUnderside` runs during decoration after rim installation. It changes only BEDROCK at the chunk's minimum Y and only inside the finite width. The wall's saved material palette, periodic noise, seed and rare accents are reused, with its vertical pattern folded across width from the nearest outer rim. Decay does not perforate this layer. Higher bedrock and existing non-bedrock blocks remain unchanged. There is no build-height extension or global saved-chunk retrofit. New chunks receive the layer; the runtime installer check additionally converted one existing 16×16 test patch in the active study save at chunk 22,0.

Atlas wall colour now comes from `RingWallTexture`, using the same `RingWallPattern` and `RingIndustrialElements` routines rather than the old approximate GLSL noise. Four strips cover the two inner and outer faces. Native images are generated on the existing serial worker, cancelled on obsolete jobs, and released with stale/failed results. A fourth sampler is bound through each loader/version's GPU adapter. Uploads retain the >=16ms diagnostic. Width follows the display budget (capped at 16,384); each face is capped at 512 vertical samples. At the current 16,384×160 wall size, the extra GPU texture is 40 MiB. It rebuilds with the mesh, rather than on each incomplete Atlas colour update.

The texture carries map-colour materials, coherent top decay and shaded machinery/channel motifs. It does not add the real wall's block relief to the coarse mesh. Feature anchors are estimated from the captured Atlas terrain heights; incomplete/coarse Atlas data can differ from the generator's three full-resolution noise queries. Wall height is decoded in intrinsic world Y rather than incorrectly using the cylinder radius. Existing terrain lightmap, rain haze, texture morph and depth handoff remain in place. No distant underside mesh was added in this change.

Validation: both loader builds and 434 JVM tests per loader pass on 26.1.2 and 26.2. Python suite passes 429 tests with two platform skips. Fabric 26.2 launched and rendered the new sampler without shader errors. The actual underside installer converted all 256 bedrock blocks at Y−64 in chunk 22,0; all 1,280 blocks in the five layers above stayed unchanged, and the second pass was idempotent. `scripts/wall_concepts/UndersideProbe.java` retains this check. Evidence is under `logs/wall-elements-scale`: `underside-check.txt`, `underside-atlas-26.1.log`, `underside-atlas-26.2.log`, `underside-python.log`, and `underside-runtime.log`.

The generated four-face colour texture was also exported and visually checked (`generated-wall-texture.png`). The current new-world style is Industrial structures, thickness 7, **100% decay**, so many upper motifs are removed by its saved decay setting. The current Atlas is still generating. Runtime client remains open in `New World (1)`; normal source Atlas fidelity was restored after launch. Fresh multiplayer and full release qualification were not run.
